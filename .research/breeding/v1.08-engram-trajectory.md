# v1.08 — Engram-assisted trajectory memory

## Starting point

v1.07 established a 16-D INT8 latent bank with 32-state L1 retrieval and a fixed-point trajectory prior. On the recorded synthetic sequential workload it improved retrieval from 90.8258% to 95.4367% (+4.6108 percentage points), while memoryless degradation stayed at 0.0000 pp. Those numbers are historical host evidence from v1.07, not new board measurements.

## Hypothesis

An Engram-style sparse key → successor table can capture repeated latent/context transitions without a dense 32×32×32 table. The table should only intervene after a key has been observed at least twice, preserving the v1.07 raw-retrieval fast path for novel or ambiguous keys.

## Design

- 32 fixed slots, 16-byte INT8 key, successor state, confidence, age, and used flag.
- FNV-1a-style integer hash with four bounded probes.
- Replacement is age-biased; no heap, float, or unbounded loop is used.
- A repeated key with confidence ≥ 2 may override raw nearest-state retrieval.
- Every query updates the successor memory, allowing forward-only online adaptation.

## Checks

`benchmarks/v108_reference.py` is deterministic (`seed=108`) and reports raw versus aided accuracy, activation, and harmed queries. The C implementation is written for `-std=c11 -Wall -Wextra -Werror`; the host mirror is C++17.

Recorded host run (100,000 samples, seed 108): raw accuracy **77.5280%**, Engram-aided accuracy **77.1920%**, activation **32.5180%**, and **3,193** harmed queries. This is a failed quality gate: the 16-wide bucket creates collisions across nearby latent states and the bounded confidence rule cannot reject all of them.

## Status

Host reference: IMPLEMENTED; quality gate: **FAIL / NO-GO** until key design is revised. Physical ESP-IDF build/flash/run/serial evidence: NOT AVAILABLE IN THIS COMMIT. Therefore `BOARD-PASS=NO`.

## Provenance and licensing

The research direction is a clean-room synthesis of the public Engram ideas (sparse associative key/value memory and bounded retrieval) with the project’s v1.07 trajectory prior. No third-party source code is copied into this branch; verify upstream licenses before importing implementations.
